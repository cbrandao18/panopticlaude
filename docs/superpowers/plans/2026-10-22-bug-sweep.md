# Bug Sweep Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Grow `dd-triage-bot` into one daily bug sweep. It covers Datadog for all prod, and Sentry plus LogRocket for staff-fe, with cross-correlation. Results show on the panopticlaude dashboard and in the midday brief, and fixers start automatically for simple bugs.

**Architecture:** The bot keeps its Orca automation, `PROMPT.md` and logs. New source steps live in `sweep-sources.md`, which `PROMPT.md` reads. Deterministic pieces are small stdlib Python scripts with `--selftest`, matching the daily-brief scripts:
- `findings.py`: findings store, run metadata, screenshot cleanup
- `fix-guard.py`: fixer skip rules
- `start-bug-fix.sh`: copy of `start-hotfix.sh`

A mode file gates the cutover. The dashboard gets two read-only routes plus a findings view.

**Tech Stack:** zsh, `/usr/bin/python3` (stdlib only), Node 24 with `node:test` (dashboard, no dependencies), the Orca CLI, `gh`, `pup`, claude.ai LogRocket and Sentry connectors, and a key-based LogRocket MCP server.

## Review Focus

1. **A source fails or returns 403 (wrong account, connector missing).** The run must record that source as `failed: <reason>`, not as zero findings. The dashboard header shows a failed badge, and the brief says so. Tests: Task 2 `run-meta`, Task 4 status payload, Task 5 rendering.
2. **The screenshot route gets traversal, symlinks or non-PNG names.** These must return 404 and never read outside `shots/`. Test: Task 4.
3. **`findings.json` is missing, empty or half-written.** The dashboard shows "No findings yet" or a readable error and doesn't crash. Writes are atomic (temp file plus rename). Tests: Tasks 2 and 4.
4. **The same defect arrives from a second source, or on a later day.** It merges into one record, keeps its ticket, and doesn't double-count. Test: Task 2 merge selftest.
5. **A fixer gets a pre-cutover, owned or Joe-routed ticket.** It skips with a reason and creates nothing. Test: Task 6 selftest cases.

### Task 2: `findings.py`, the findings store, run metadata and screenshot cleanup

**Files:**
- Create: `$BOT/findings.py` (`#!/usr/bin/python3`, stdlib only, with a header usage comment like `refresh-brief.py`)
- Create: `$BOT/sweep-config.json` containing `{"mode": "dry-run", "cutoverAt": null}`
- Creates at runtime: `$BOT/findings.json`, `$BOT/shots/`

**Interfaces:**
- Produces, as the schema of `findings.json`:
  ```json
  {"version": 1,
   "lastRun": {"at": "ISO", "mode": "dry-run|file|file+fix",
               "sources": {"datadog": "ok|failed: <reason>", "sentry": "...", "logrocket": "..."},
               "counts": {"issuesSeen": 0, "sessionsReviewed": 0, "routesReviewed": 0, "filed": 0, "correlated": 0}},
   "findings": {"<key>": {"key": "", "title": "", "where": "", "env": "",
       "sources": [{"type": "datadog|sentry|logrocket", "url": "", "count": 0, "countLabel": "sessions|users|events/day", "firstSeen": "ISO", "lastSeen": "ISO"}],
       "screenshot": "<file>.png|null", "ticket": 123, "borderline": false,
       "fix": {"status": "none|pr|not-simple|blocked|merged", "url": null, "reason": null},
       "filedAt": "ISO|null", "updatedAt": "ISO"}}}
  ```
- Produces, as a CLI. Every write goes to a temp file in the same directory, then `os.replace`.
  - `findings.py upsert <records.json>`: merges a list of finding records. Sources are keyed by `type` and `url`. `count` takes the newest value, `firstSeen` the minimum, `lastSeen` the maximum. An existing `ticket` and `fix` are never overwritten by null.
  - `findings.py run-meta <meta.json>`: replaces `lastRun`.
  - `findings.py set-fix <issue> <status> [<url-or-reason>]`
  - `findings.py pending-fixes`: prints one issue number per line. That means findings with a `ticket`, `fix.status == "none"`, `borderline == false` and `filedAt >= cutoverAt` from `sweep-config.json`. It prints nothing when `cutoverAt` is null.
  - `findings.py backfill`: adds the open `[Bug AI Automation]` tickets from `gh search issues --repo gobranch/branch --state open --limit 200 "[Bug AI Automation] in:title"` as Datadog-sourced records, with `filedAt` set to the ticket's creation time.
  - `findings.py prune-shots [--days 14]`
  - `findings.py --selftest`

**Interfaces:**
- Consumes: Task 2 `findings.py set-fix` and `sweep-config.json`.
- Produces:
  - `skip_reason(issue: dict, status: str | None, branches: list[str], cutover_at: str | None) -> str | None` in `fix-guard.py`. `issue` is the JSON from `gh issue view N --json number,title,body,createdAt,assignees,comments,closedByPullRequestsReferences`.
  - CLI `fix-guard.py <issue>` prints `ok` or `skip: <reason>`. It gets `status` from the issue's BRANCH TECH project item, through GraphQL `projectItems` with the Status field, and gets `branches` from `gh issue develop --list N`.
  - `start-bug-fix.sh <issue>` prints `started`, `skip: <reason>` or `error: …` as its last line.
  - `fix.log` lines are `<ISO-8601 with offset> <outcome>`, where the outcome is one of `started #N`, `pr #N <url>`, `not-simple #N: <reason>`, `clear #N <url>`, `blocked #N <url> <pending>`.

`skip_reason` checks these rules in order:

| Rule | Reason printed |
|---|---|
| `cutover_at` is None, or `createdAt` is before it | `filed before cutover` |
| the title doesn't start with `[Bug AI Automation]` | `not a sweep ticket` |
| it has assignees | `assigned to <logins>` |
| `status` is anything other than None, `Needs Refinement`, `Design Refinement` or `To Do (Dev)` | `status <status>` |
| `branches` or `closedByPullRequestsReferences` is non-empty | `has branch or PR` |
| a comment matches `(?i)\b(i'?ll take|taking (this|it)|i'?m (on|working on) (this|it)|on it)\b` | `claimed by @<login>` |
| the body contains `### Software Dev\nJoe Emison` or `### Dev Team\nJoe / Ivan` | `Joe/Mutuals-routed` |

Otherwise it returns None.
